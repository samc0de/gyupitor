# Full-Stack Application Design Specification

This document outlines the design for a simple web application to display BigQuery query recommendations.

## 1. Overview

The application consists of a Python backend that serves recommendations from a JSON file and a static HTML frontend that displays them. The entire application is containerized using Docker Compose for easy deployment and scalability.

## 2. Backend Design

The backend is a lightweight Python web service using the FastAPI framework.

### Tech Stack
- **Framework**: FastAPI
- **Language**: Python 3.9+
- **Server**: Uvicorn

### API Endpoint

- **Endpoint**: `/api/recommendations`
- **Method**: `GET`
- **Description**: Retrieves the query performance recommendations.
- **Success Response**: `200 OK` with a JSON array of recommendation objects.
- **Data Source**: The API will read the `recommendations.json` file located at `src/me/bq_app/analysis/recommendations.json` and return its content directly.
- **Database**: No database is required for this service. The application is designed to be stateless, reading from the file system on each request or caching the content in memory upon startup.

### File Structure (Backend)
```
backend/
├── app/
│   ├── __init__.py
│   └── main.py
├── Dockerfile
└── requirements.txt
```

## 3. Frontend Design

The frontend is a single-page static web application.

### Tech Stack
- **HTML5**
- **CSS3** (minimal styling)
- **JavaScript** (for API communication)

### UI Components
- **Title**: A main heading for the page, e.g., "BigQuery Performance Recommendations".
- **Recommendation List**: A dynamic list where each item displays the details of a recommendation (`job_id`, `project_id`, `total_slot_ms`, and `recommendation`).

### Behavior
1. On page load, the JavaScript will make a `GET` request to the backend's `/api/recommendations` endpoint.
2. The fetched JSON data will be parsed and rendered into the recommendation list.
3. The UI will display a loading message while the data is being fetched and an error message if the API call fails.

### File Structure (Frontend)

frontend/

└── Dockerfile

The application will be orchestrated using Docker Compose.

### Service Details

- **`frontend` service**:
  - Builds from the `./frontend/Dockerfile` which will set up an Nginx server.
  - Serves the static `index.html` file.
  - Exposes port `8080`.
  - Depends on the `backend` service to ensure the backend is available before the frontend starts.
